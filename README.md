# «Последний кислород» — Ink-сценарий для «Станции-7»

Готовый сценарий на [Ink](https://www.inklestudios.com/ink/) для игровой сцены
(базовая сетка 100×100, герой `hero.glb`, HP 100).

Кислородный насос станции остановился. Герой должен найти топливо, запустить
энергоустановку, починить перекушенный кабель — и успеть до нуля процентов.

---

## 1. Как подключить сценарий

1. Откройте раздел **«Сценарий»** в редакторе игры.
2. Оставьте режим **«Git репозиторий»**.
3. В поле **«Ссылка на Git-репозиторий»** вставьте адрес этого репозитория:

   ```
   https://github.com/<ваш-логин>/station-7-scenario
   ```

4. В поле **«Ветка Git-репозитория»** оставьте `main`.
5. Нажмите **«Сохранить сценарий»**.

Репозиторий должен быть **публичным** — приватные платформа не читает.

Точка входа в сценарии — узел `start` (первая строка кода `-> start`).
Если платформа спрашивает файл явно — это `main.ink` в корне репозитория.

## 2. Что внутри

| Файл | Назначение |
| --- | --- |
| `main.ink` | весь сценарий: пролог, двор-хаб, 8 локаций, 7 концовок |
| `globals.csv` | те же глобальные переменные в виде таблицы — для быстрого ввода в UI |
| `docs/globals.md` | описание каждой переменной: тип, стартовое значение, где используется |
| `docs/scene-map.md` | какой объект сцены (из «Загрузки объектов») за какой узел отвечает |
| `tools/build.mjs` | компиляция `main.ink` → `build/main.json` (для проверки локально) |
| `tools/playtest.mjs` | автотест: 300 случайных прохождений, поиск тупиков и ошибок |

Сценарий — один файл, без `INCLUDE`: так его точно прочитает любой загрузчик.
Если захотите разбить на главы, Ink поддерживает `INCLUDE chapters/01_angar.ink`,
но проверьте, что платформа тянет связанные файлы.

## 3. Глобальные переменные

В сценарии объявлено 17 переменных (лимит платформы — 42, имя ≤ 12 символов, латиница).
Полная таблица с назначением — в [`docs/globals.md`](docs/globals.md).

| Имя | Тип | Старт | Смысл |
| --- | --- | --- | --- |
| `hp` | число | 100 | здоровье героя |
| `oxygen` | число | 100 | запас кислорода, % |
| `energy` | число | 0 | энергия в сети станции (0/1) |
| `scrap` | число | 2 | металлолом — «валюта» ремонта |
| `fuel` | число | 0 | канистры топлива |
| `water` | число | 3 | вода: поить пса, торговаться с пауком |
| `trust` | число | 0 | доверие машин (робот, паук, пёс) |
| `datachip` | число | 0 | чипы данных «ЗАРЯ» |
| `day` | число | 1 | сутки |
| `alert` | число | 0 | уровень тревоги дронов |
| `snake_fixed` | флаг | false | кабель сращён |
| `gen_on` | флаг | false | энергоустановка запущена |
| `gate_open` | флаг | false | ворота разблокированы (пёс пропускает) |
| `dog_friend` | флаг | false | пёс стал союзником |
| `spider_dead` | флаг | false | страж шахты обезврежен |
| `know_truth` | флаг | false | герой узнал правду о «добровольцах» |
| `ending` | число | 0 | код концовки (10/11/12/20/21/30/31) |

### Важно про дубликаты

Переменные объявлены прямо в `main.ink` (блок `VAR` в строках 10–26) — так сценарий
работает сам по себе, даже если панель «Глобальные переменные» пустая.

* Если платформа **сама** объявляет переменные из панели и ругается на повторное
  объявление — удалите блок `VAR ...` из `main.ink` и заведите переменные в панели
  с теми же именами и стартовыми значениями (данные из `globals.csv`).
* Если панель только **читает** переменные из сценария — ничего делать не нужно,
  просто нажмите «Добавить переменную» и перенесите имена, чтобы видеть их в отладке.

Имена короче 12 символов и только латиница — под лимит платформы подходит всё.

## 4. Объекты сцены и эффекты

Сценарий ссылается на уже загруженные объекты через теги `# scene:...` и `# effect:...`
(подробная таблица — [`docs/scene-map.md`](docs/scene-map.md)):

* **проходимое окружение:** `grass`, `flowers`, `pebbles`, `asphalt`
* **непроходимое:** `angar`, `gas_station`, `Oxygen_Pump`, `Hybrid_Energy_Plat`,
  `platform`, `column`, `rock_1`, `rock_2`, `skalal`, `trees`, `building_2`,
  `Cable_calm`, `cabel_snake`
* **интерактивные:** `rt_70`, `hydropic`
* **NPC:** `robot`, `pavuk`, `like_dog`
* **эффекты:** `ветер` (фон двора), `дождь` (финал)

Если платформа теги не понимает — они безвредны, это просто комментарии-метки,
по которым удобно связывать узлы сценария с объектами на сцене.

## 5. Карта ветвления

```
start → start_gate → yard (хаб)
                       ├─ pump / energy_plant / gas_station → gas_station_talk
                       ├─ cable → snake_fixed
                       ├─ spider → spider_loot → know_truth
                       ├─ dog → dog_friend, gate_open
                       ├─ rt70, hydroponic (ресурсы)
                       └─ gate → end_leave / end_leave_dog
pump_start (energy>0 && snake_fixed) → epilogue
                       ├─ 10 «Живой воздух»   — базовый хороший финал
                       ├─ 11 «Добровольцы»    — если знал правду (know_truth)
                       ├─ 12 «Уровень минус один» — секретный (spider_dead + dog_friend + trust>2)
                       ├─ 20 «Снаружи»        — ушёл один
                       ├─ 21 «Вдвоём»         — ушёл с псом
                       ├─ 30 «Тишина»         — hp = 0
                       └─ 31 «Ноль процентов» — oxygen = 0
```

Хаб сделан так, что застрять нельзя: у каждой локации есть «выход» (`+`-выбор,
он не исчезает после первого использования), а ворота доступны всегда.

## 6. Локальная проверка

Нужен Node.js 18+.

```bash
npm install          # поставит inkjs
npm run build        # main.ink → build/main.json, ошибки компиляции в консоль
node tools/playtest.mjs   # 300 случайных прохождений: ищет тупики и ошибки
```

Последняя проверка этого сценария:

* компиляция — без ошибок и предупреждений;
* 300 случайных прохождений — без `RUNTIME ERROR`;
* достижимы все 7 концовок.

## 7. Как править

* Удобнее всего — в [Inky](https://github.com/inkle/inky/releases) (бесплатный
  редактор Ink с подсветкой и проигрыванием прямо в окне).
* Или в VS Code с расширением **Ink**.
* После правок: коммит в `main` → в редакторе игры нажмите «Сохранить сценарий»
  ещё раз, чтобы подтянулась новая версия репозитория.
* Если правите текст, следите за отступами: в Ink отступ = уровень вложенности
  выбора. Четыре пробела, как в файле.
